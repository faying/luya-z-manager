日志 `.cache/baseline-idle-20260916-160351.log`，30 个采样点，跨度 29 分钟。
条件：电池供电（`usb=0`）、熄屏（`backlight=0`）、Wi-Fi 客户端 0 个、mihomo 未运行。

| 指标 | 中位数 | 范围 |
|---|---|---|
| **691MHz 驻留** | **78.65%** | 窗口内增量 142403 / 181057 ticks |
| 4 核空闲率 | 85.6% | idle 增量 595731 ticks / 1740 s |
| cpuss 温度 | 42.3 ℃ | 41.3 – 44.9 |
| xo 温度 | 38.3 ℃ | 38.0 – 39.4 |
| 电池温度 | 35.0 ℃ | 34.0 – 36.0 |
| 放电电流 | 292 mA | 244 – 425 |
| MemAvailable | 716 MB | 713 – 720 |

频率分布：691MHz 占 78.65%，1516800 kHz 占 6.70%，其余各档都在 3% 以内。
空闲时在最低频和一个中频档之间跳，没有长期停在高频。

### 读这组数字时必须知道的三件事

1. **电流峰值 425 mA 是自己造成的，不能当设备行为用。** 测量窗口里跑了几条 ssh 探测
   （查 dropbear 会话、试 nohup、验死人开关）。中位数只从 288 动到 292，所以
   **中位数可用、峰值不可用**。脚本报中位数和范围而不报平均值，就是为了这个：
   平均值会被少数被污染的点拉偏，而且事后看不出来。
2. **驻留率必须用首尾差值算，不能用绝对计数。** `time_in_state` 是开机以来的累计值
   （691MHz 那档基线开始时已经是 495 万 ticks），直接拿绝对值算出来的是开机至今的
   驻留率，会比实际窗口好看得多。
3. **这台设备 cpufreq 只有 `policy0`，4 个核共用一条曲线**，所以驻留率是全机的，不是单核的。
   另外 loadavg 长期在 3.3 左右，是 `smcinvoke_adci_` 和 `Sitronix Monito` 两个 D 状态
   内核线程撑起来的，不是真负载——同期实测 85.6% 空闲。

### 设备当时是干净的（两路独立确认）

- 设备侧：dropbear 只有 1 个监听进程 + 2 个会话（采样器和一条临时 shell），全部有归属；
  4 个核的 idle 计数增长均匀，没有某个核被占满。
- 会话侧：同期在做触屏 v2 的会话确认全程没有 ssh 进设备。

## 这份基线的前提是否成立（2026-09-16 阶段零已验证）

第 1 组那 78.65% 的 691MHz 驻留，前提是**国内流量在内核层就绕开 mihomo、不进用户态**。
阶段零实测发现原设计实现这一点的两个机制都不可用，但换了路子之后前提仍然成立：

- ✗ `auto-redirect: true` 起不来 —— 设备是 `iptables v1.8.8 (legacy)`，legacy 已占住
  `raw mangle nat filter` 的 hook，mihomo 用 nftables 建链时内核回 EEXIST
  （`netlink receive: file exists`），TUN 整个建不起来。
- ✗ `route-exclude-address-set: [cn_ip]` 随之失效 —— 它依赖 auto-redirect 建立的
  nft 来打 mark，关掉 auto-redirect 后国内 IP 和被墙 IP 一样全进 TUN。
- ✓ 改用**静态 `route-exclude-address` 全量 CN CIDR**（9646 条）可行：走纯 ip route，
  不碰 nft。实测 `table 2022` 51 → 12731 条，4 秒内注入完毕，内存开销约 35–42 MB，
  国内 IP 确实绕行、被墙 IP 仍走 TUN。

所以第 2、3 组仍按原口径采集，第 1 组的数字继续有效。但第 3 组要额外留意：
12731 条路由本身的内存与查表开销已经包含在内，不要把它误算成代理带来的增量。
