# DESIGN.md — ZTE U60 Pro（MU5250）界面设计单一事实来源

这份文件是**唯一**的设计基准（工作区根目录 `DESIGN.md` 只是指向这里的指针）。`source/touch-ui/docs/UI-GUIDE.md` 和 `source/manager/.impeccable.md` 保留为实现细节文档，与本文件冲突时以本文件为准。

来源：`/plan-design-review` 2026-09-16（决定 1A / 2A / 3A / 4A / 5A / 6A / 7A / 7B / 7C）。

---

## 1. 通用原则（两个平台都适用）

1. **状态和原因永远是第一优先级**，可改的东西第二，明细（流量、连接数、日志）放最后。
2. **状态不能只靠颜色**。任何状态都同时有符号和文字：`●` 正常、`▲` 警告、`■` 停止。
3. **空状态是功能**。不允许只写「无数据」，必须给出原因和下一步动作。
4. **减法优先**。元素要为自己的像素负责，装不下就砍，不靠装饰填空。
5. **卡片只在卡片本身就是交互时使用**。纯展示的分组用标题加分隔线。

---

## 2. 状态语义（跨平台，语义不可变）

| 语义 | 含义 | 符号 | 触屏取值 | 后台 token |
|---|---|---|---|---|
| 正常 | 代理运行中 | `●` | `.ok` `#5ec85e` | `--ds-success` |
| 警告 | 降级但网络可用、或有需要注意的偏差 | `▲` | `.warn` `#d98a00` | `--ds-warning` |
| 停止 | 代理未运行，需要人介入 | `■` | `.bad` `#d9534f` | `--ds-error` |
| 中性 | 用户主动关闭、暂停、上游不适合接管 | `●` 灰 | 主题默认文字色 | `--ds-text-dim` |

**颜色取值可以随平台变，语义映射不可变。** LVGL 版触屏若换色板，必须保持这四种语义的一一对应，否则同一台设备上两代界面会互相矛盾。

对比度要求：任何状态文字在所属背景上 ≥4.5:1。触屏要在 `body.dark`（`#15161a`）和 `body.light`（`#eceef1`）两套背景下分别验证。

完整的 15 行状态文案表（含 API 不可达、空列表、订阅失败、切换成功）在设计文档的「界面设计决定 · 2A」一节，实施时以那张表为准。

**状态历史保留 20 条**（决定 3A），两个平台共用同一份数据。超过 20 条丢最旧的。触屏底部只渲染最近 1 条，后台在「高级」区展开全部 20 条（带时间、状态、原因和关键数值）。历史为空时不渲染该行，不显示「暂无记录」。

数据来源是 `/data/chill/events.log`（落 `/data`，重启不丢；`chill.sh` 每次状态迁移追加一行，写入时截断到最后 20 行）：

```
2026-09-16T03:12:41 overheat cpuss=86 -> direct
2026-09-16T03:29:07 recover  cpuss=63 -> running
```

触屏底部那一行由它渲染成：`最近：03:12 过热暂停 · 03:29 已恢复`。
这份历史同时是温控阈值标定的依据——跑几天看实际触发次数，再回填 `CHILL_TEMP_HOT_*`，所以格式不要随意改。

## 3. 触屏 · 阶段一（litehtml，现役二进制）

**硬约束**（违反会直接画不出来或显示成豆腐块）：

| 能用 | 不能用 |
|---|---|
| `block` / `inline-block` / `float` / `table` 布局 | CSS Grid、JavaScript、CSS 动画与过渡 |
| 颜色、圆角、边框、padding、margin | 图片（`<img>` 与 `background-image` 都画不出） |
| `position: absolute / relative` | `var()` 自定义属性（不可靠） |
| 页面整体竖向滚动 | 元素内部滚动容器 |

- 屏幕 320×480。页面文件放 `ui/functions/`，改完热生效，不用编译。
- **符号白名单**（设备字体确认可显示）：`● · ↑ ↓ ▲ ▼ ℃ •`。其余符号先在设备上验证，拿不准就用中文或 CSS 画。
- **文案长度上限 14 个汉字**（决定 2A）。320px 宽单行放得下的极限，超了会截断或换行破坏层级。状态表里每一条触屏文案都按这个写。
- **磁贴文案**（决定 7C）：`chill.html` 的 `<title>` 保持 `CHILL`，`<meta name="description">` 写 `线路与出口`。这是磁贴墙上的副标题，和「网络测速」「eSIM」同一风格；不用英文口号。
- 主题用 `body.dark` / `body.light` 两套规则实现，每个新颜色类都要写两遍。
- 页面只保留 `<body>` 内层，不写 `<style>`、不写 `{{STATUSBAR}}` 之外的壳、不自加返回栏。
- 轮询规则：只在 CHILL 页可见且亮屏时请求 API；首页卡片只读 `/tmp/chill.state`，不打 API；速率取累计字段，默认不拉全量连接；测延迟只在点击时触发。

**CHILL 页层级**（自上而下）：状态行（状态 + 出口地区 + 延迟，大字）→ 模式按钮 → 组 → 节点列表 → 底部一行流量与连接数 → 底部一行最近事件（无事件时不渲染）。

## 4. 触屏 · 阶段三（LVGL 重写）

v2 触屏用 C + LVGL 9.5 重写，320×480，FreeType 渲染 CJK。继承第 2 节状态语义映射、第 1 节通用原则（状态第一/不只靠颜色/减法优先/卡片只在卡片本身就是交互时使用）、事件历史行的存在与位置、轮询规则。以下是 LVGL 侧的具体化（2026-09-18 定稿，此前两轮实现——发光玻璃卡片、彩色左边框卡片——都违反了第 6 节反面清单，返工过）：

**布局：少而密的卡片，不是一堆单指标卡片碎片。** 2026-09-18 第一次尝试把这条理解成「完全不用卡片背景」，跟真机上已经在跑的 litehtml 版（`ui/01-signal.html`）对比后发现理解错了——旧版信号页正是靠「一张卡片塞进运营商/制式/载波数/带宽/QCI/AMBR/频段/RSRP/SINR/ARFCN/PCI 这十来项」做到信息密度高，卡片本身是纯深色实底圆角块，不带边框、不带阴影发光、不带彩色装饰。第 6 节反面清单真正禁止的是**一个指标一张卡片**（信号一张、电池一张、流量一张……上下堆成马赛克）和**装饰性卡片效果**（发光玻璃、彩色左边框、渐变），不是禁止卡片这个容器本身。所以：相关字段合并进同一张卡片（信号+制式+载波详情算一组、电池+流量+设备+系统算另一组），卡片是纯色实底、圆角、无边框无阴影；只有当内容本身是可点的交互对象时才用背景色块区分（eSIM 行、设置页分段按钮），这条不变。

**字号阶梯**（FreeType CJK 字号 / Montserrat 数字字号，一一对应）：
- 分节标题（caption）：CJK 13px（`FCN_S`），纯数字场合用 montserrat 14px，颜色 `UI_C_TEXT_3`。
- 正文/数值：CJK 13-16px，纯数字 16px，颜色按语义（`UI_C_TEXT`/`UI_C_TEXT_2`/状态色）。
- 强调数值（信号 RSRP、流量速率这类一眼要看到的数字）：montserrat 16-20px。
- 页面标题：CJK 16-20px（`FCN`/`FCN_L`），`UI_C_ACCENT`。
- 不新增更小的号——已经是 FreeType 运行时字号下限附近，再小在这块屏幕上不可读。

**间距阶梯**：4 的倍数（4/8/12/16px）。分节标题到内容 4-6px；同一分节内相邻行 16-20px；分节之间（含分隔线）12px 上下各半；页面左右留白 `UI_INSET=8px`，分节内容左右留白 `UI_PAD=12px`。

**分隔线**：已废弃。2026-09-21 起每一个用户可见页面（含二级页）都由卡片构成，卡片之间的 10px 间距本身就是分节，不再需要裸分节标题（`mk_section_title`）和 1px 分隔线（`mk_divider`）——两个函数已从 `src/ui.c` 删除，不要再加回来。分节标题现在一律是卡片内左上角的 caption（CJK 13px `FCN_S`，`UI_C_TEXT_3`）。唯一例外是「性能测试」二级页（FPS/触控上报率/动画方块），它是开发期调试页，不是给设备使用者看的，正式版本里要么删掉要么藏起来。

**页面结构（2026-09-21 重构，照搬现役 litehtml 版）**：四个可横滑的顶层页面 + 一层二级页，底部四个 tab（图标 + 中文标签）。原来那版六个平铺 tab 里有一个我自己发明的「网络」页，内容跟首页信号卡重复，已删除；WiFi 和 eSIM 从顶层降级成二级页，跟旧版一致。
- **首页**：信号卡（汇总行 + 每载波子卡片）。载波列表**必须先放服务小区**（从 `nr_band/nr_bw/nr_rsrp/nr_pci/nr_channel` 这几个主字段构造），再把 `nrca` 里的每一组原样追加——`nrca` 只给配置载波，服务小区在里面（如果在）是 RSRP 地板值，htmlmain.c 就是这么拼的。只读 `nrca` 会出现"明明连着网，卡片上 2 个载波全是未激活"。、Tailscale 卡、CHILL 卡。汇总行是重点：`制式 · 载波数 · 总带宽`（如 `5G SA · 3 NR 载波 · 240 MHz`），对应 htmlmain.c 的 `total_show_bw`。每个激活载波两行：大号频段+带宽、RSRP 和 SINR **都按质量分色**（RSRP -85/-105，SINR 13/0，跟 `car_row()` 同档）、右侧 ARFCN/PCI；未激活载波（RSRP 到 -140 地板值）压成一行，只留频段、未激活标记和 ARFCN/PCI——它的信号数字是哨兵值，不值得占两行。
- **图表**：CPU / 内存 / 网速（上下行两条线）/ 电池，`lv_chart` + `lv_chart_set_next_value()`，固定点数、原地移位，每秒更新不分配内存。网速走 log10 刻度（这条链路从几百 B/s 到几十 MB/s，线性轴会把除峰值外的一切压在底边）。
- **功能**：2×N 磁贴墙，副标题带实时状态（短信条数/未读、CHILL 运行状态、WiFi SSID+客户端数）。点磁贴进二级页。
- **系统**：屏幕（亮度+自动息屏）、电池与负载（从首页挪过来）、设备（版本/IMEI 打码/USB/固件）、开关、切换原厂界面。
- **二级页**：WiFi（热点信息 + 五个开关 + 客户端列表 + DHCP）、短信、信令读取（服务小区/网络/支持频段）、锁频（选网方式 + 三组频段多选 + 恢复默认）、测速、CHILL（状态 + 模式三段 + 节点列表带延迟分色）、eSIM、性能测试（调试）、Tailscale（本机身份 + 节点列表，直连/中继/在线/离线分色）。Tailscale 这一页**不在磁贴墙上**，入口是首页那张 Tailscale 卡片本身——磁贴列表用一张显式的 id 表，不是遍历 0..SUB_N。二级页层是 `lv_screen_active()` 上盖在 tileview 之上的一个容器，**不是** `lv_layer_top()`——顶栏和 tab 栏在 layer_top，必须继续盖在二级页之上，跟旧版二级页保留状态栏一致。

**会改设备状态的控件一律两段确认**：锁频、选网方式、恢复默认配置、切换原厂界面——第一次点变橙色写「再按一次确认」，5 秒内再点才真下发。这块屏 320px 宽，误触代价是掉网或掉出界面，跟 eSIM 切换用的是同一套 arm/confirm 模式。WiFi 的五个开关是例外（lv_switch 本身就有明确的开关语义，且立刻可以再拨回去）。

**没有数据源的功能，页面要说清楚缺什么，不要画空壳**：本机 zwrt-datad（C 0.9.48）的路由表里没有 `/modem/latest-signals`，所以 MIMO/层数/RB/BLER 和邻小区列表**在这台设备上拿不到**——信令读取页展示 /state 里真实有的东西（服务小区、选网、支持频段），缺的那部分写明原因。测速需要 `/data/plugins/better-speedtest/`，本机没装，页面直接说明，不做没有后端的仪表盘。

**页面滚动容器**：超过一屏的页面用 `mk_scroll(tile, content_h)`。容器高度必须是**可视高度**（`UI_VIEW_H = 480 - 24 顶栏 - 36 底部导航 = 420`），子元素高度超出它——LVGL 只滚动"子元素超出容器内容区"的那部分。早期写法把容器高度设成内容高度（Home 660 / 网络 480）、子元素全在里面，`lv_obj_get_scroll_bottom()` 恒为 0，结果是底部内容被裁掉且怎么拖都不动（网络页的 `支持` 频段行一直验证不到，就是这个原因，不是手势没生效）。滚动范围由容器底部一个 1×1 透明占位子元素钉住，不依赖最后一张卡片的高度，这样运行时按数据量收缩卡片不会改变手指下的滚动范围。

**信息密度**：一屏能放下的分节数据点，按第 1 节「减法优先」的反面——**没有理由把能放进一屏的数据拆成多屏**。反过来也成立：首页只放信号相关的内容（信号/Tailscale/CHILL），电池、CPU、内存、运行时间这些系统读数 2026-09-21 从首页挪到了「系统」页，紧挨着画它们曲线的「图表」页——首页在参照的 litehtml 版里就是信号页，不是仪表盘。

**嵌套子卡片（2026-09-18 定稿，用户明确要求锁定这版风格，非请勿改）**：一张卡片内如果要展示"一组同形状的多字段条目"（典型例子：载波聚合激活时，每个分量载波都要展示频段/带宽/RSRP/RSRQ/SINR/ARFCN/PCI 这一整套字段），每个条目单独套一层子卡片——细描边（`lv_color_white()` `LV_OPA_20`，圆角 10px，跟父卡片同色底，不额外加填充色区分），不是全部挤成一段换行文字。这不违反"卡片只在卡片本身就是交互时使用"：子卡片对应的是一整组有意义的字段（一整个载波的完整状态），不是单指标碎片化。子卡片数量必须固定预建、按需隐藏/显示（当前 Home 页固定 5 个载波槽位＝3 NR + 2 LTE，WiFi 页 5 个客户端槽位，CHILL 页 8 个节点槽位，超出在标题右侧写 `5/6 台` 这样的计数），不能跟着数据量动态创建/销毁对象——这是内存安全约束不是风格选择，理由见下方「已知踩过的坑」。外层卡片高度和它下面的卡片位置要跟着实际条目数动态收缩（`lv_obj_set_height`/`lv_obj_align` 每次刷新重算），不能固定按最大槽位数留空。

**卡片内部字号/颜色层次**：卡片内容不能都用同一个字号——标题类文字（如"n78 100M"这种频段+带宽）用 montserrat 16px 或以上，比明细数字（RSRP/ARFCN/PCI 这类）大一档，否则整块读起来是"一坨"没有层次（2026-09-18 真实踩过、用户明确指出过这个问题）。有好坏语义的数值（如 SINR：≥13 良好、0-13 一般、<0 差）要用状态色区分（`UI_C_OK`/`UI_C_WARN`/`UI_C_BAD`），不能所有数值都用同一个灰色——RSRP 这类没有简单好坏阈值的数值保持中性色，不要连带染色。

**固定顶部状态栏**：时间、信号点+制式、上传下载速率、电池（描边电池图标+比例填充，不是文字百分比或图形符号叠加——充电状态用换填充色表示，不要在小图标里叠加闪电符号，字号不够小会溢出，真机截图验证过两次都溢出，第三次才改成纯色块方案），跨所有页面共享（`build_statusbar()`，独立于 `lv_tileview` 之外，不跟着翻页滚动）。页面内容里不要重复顶部栏已经展示的信息（如页面卡片里不需要再单独放一份信号格数图标或电量百分比），页面内容应该展示顶部栏放不下的详细信息。

**已知踩过的坑**：
- `LV_USE_STDLIB_MALLOC` 曾经设成 `LV_STDLIB_BUILTIN`（LVGL 自己划一块跟系统内存完全隔离的小内存池，从 128KB 一路加到 2MB 都还在崩），根因是这个隔离本身——litehtml 版（`htmlmain.c`）直接用系统 `malloc()`，面对的是整机 690MB+ 可用内存，从不出这个问题。已经改成 `LV_STDLIB_CLIB`（真正的系统 malloc/string/sprintf），跟 litehtml 版走同一条路，`LV_MEM_SIZE` 相关配置全部移除（只对 BUILTIN 模式有效）。**这条是真正修复，之前"减少不必要的 `lv_label_set_text` 调用"那版只是缓解，不是根治**——但那个优化本身仍然保留，两个问题不是互斥的。
- `lv_label_set_text()`/`_fmt()` 无论新文字是否跟旧文字完全相同都会整个释放再重新申请一次文字缓冲区——每次 `refresh_cb` 刷新前先跟缓存对比，值没变就跳过调用，不要无条件每秒重设几十个标签的文字。
- 验证真机稳定性只能用"真的去读一次 `/tmp/u60-dumpfb` → `/tmp/fb.dump`，确认字节数正确"这种功能性检查，`pidof` 查得到进程不代表进程真的还在正常跑主循环（LVGL 断言失败是死循环不是真的退出，`pidof` 会一直查到它）。
- `lv_slider`/`lv_button`/`lv_switch` 的构造函数默认都打开 `LV_OBJ_FLAG_SCROLL_ON_FOCUS`（配合 `lv_obj.c` 里 `LV_EVENT_FOCUSED` 的处理），某个控件在页面构建期间一旦被 focus，会自动把自己滚动进可视区域——这个项目从头到尾只用触屏，没有 group/keypad 场景，focus 驱动的滚动毫无意义，但默认值就是开着的。表现是某个页面第一次构建时莫名其妙停在滚动到一半的位置（首次访问「系统」tab 看到的第一张卡是「电池与负载」而不是最上面的「屏幕」），之后再切进来又正常，容易被当成偶发问题。凡是用 `mk_scroll`/`mk_scroll_h` 的页面，构建函数末尾都加一行 `lv_obj_scroll_to_y(t, 0, LV_ANIM_OFF)` 钉回顶部——这行只在页面构建时跑一次，不影响用户之后自己滚动的位置。
- **字体和字形必须配对**：`LV_SYMBOL_*`（LVGL 私有区码位）只能放 montserrat 标签；中文、`·`(U+00B7)、`↓↑`(U+2193/2191) 只能放 FCN/FCN_S（设备上的 CJK TTF）。放反了两边都是豆腐块——2026-09-21 一轮截图里同时出现了两种：Tailscale 的 IP 行用 montserrat 拼 `·`、图表网速标题用 FCN_S 拼 `LV_SYMBOL_DOWN`。数字/ASCII 放 CJK 字体没问题，所以拿不准就用 FCN_S。另外 `LV_SYMBOL_DOWN`/`LV_SYMBOL_UP` **画出来是 ∨ ∧ 折角，不是 ↓ ↑ 箭头**，看着像"展开/收起"而不是上下行速率——顶栏和图表的速率一律用 FCN_S + 真正的 `↓`(U+2193) `↑`(U+2191)，跟现役 litehtml 版状态栏保持一致。
- **montserrat 标签里绝对不能出现中文**，会渲染成豆腐块方框。这个坑 2026-09-18/09-21 一共踩了四次（网络页 PLMN 行、Tailscale 状态"已连接"、载波子卡片的"未激活"后缀、WiFi 密码行的"密码未公开"）。判断标准不是"当前这个值是不是中文"，而是"这个标签**有没有可能**取到中文值"——包括兜底文案和状态词。数字/ASCII 放中文字体（`FCN`/`FCN_S`）反而没问题，所以拿不准就用 CJK 字体。
- `lv_tileview_add_tile()` **不会**设置 tileview 的"当前 tile"指针，`tile_act` 一直是 NULL，直到第一次 `lv_tileview_set_tile*()` 或第一次滚动结束（`lv_tileview.c:92,181`）。所以刚启动时虽然首页明明就在眼前，`lv_tileview_get_tile_active(tv) == s_tiles[0]` 却是 false，所有靠这个判断做可见性门控的轮询（Tailscale、eSIM）一次都不会跑——表现是首页 Tailscale 卡片永远空着，要翻到别的页再翻回来才有数据。`ui_create()` 建完 tile 后必须补一次 `lv_tileview_set_tile_by_index(tv, 0, 0, LV_ANIM_OFF)`。
- **ui_create() 里任何"把界面恢复到初始状态"的调用，都要能在控件还没建完时安全返回。** 2026-09-21 重构时 `sub_close()`（收起二级页层）顺手调了 `update_tabs()`，而 tab 栏是在它之后才建的——`lv_obj_set_style_text_color(NULL, …)` 直接段错误，进程启动即死。因为侧载测试时正式 UI 已经被 kill，厂商看门狗发现没有 UI 在画，把**整机重启**了（本项目第二次这类事故）。两条应对：受影响函数开头加 `if (!s_tabs[0]) return;` 这种建成检查；测试启动脚本改成**起不来就自动回滚**——日志写 `/data/lvgltest.log`（不是 `/tmp`，RAM 盘会被重启擦掉，正好丢掉解释崩溃的那份日志），起 8 秒后 `grep "first refresh done"`，抓不到就立刻 kill 并 `sh start.sh legacy` 拉回正式 UI。`ui_create()` 里几个 `fprintf(stderr, "ui: …")` 面包屑就是给这个检查用的。
- 侧载测试前点亮屏幕不要无脑按电源键——那是 toggle。先读 `/sys/class/leds/led:lcd/brightness`，是 0 才按；否则会把亮着的屏幕关掉，`backlight_is_on()` 变 0，所有靠它门控的轮询（Tailscale/CHILL/eSIM/WiFi 开关状态）全部读不到数据，截图看起来像布局 bug。
- 轮询门控里的 `backlight_is_on()` 在息屏时是 0，headless 截图验证（SSH + fb-dump，不碰屏幕）会让这些卡片一律空着，看起来像布局 bug。验证前先用 `touchsim /dev/input/event0 key 116` 点亮屏幕（自动息屏设为"常亮"时，UI 自己永远不会开背光，只有电源键会）。

## 5. 后台管理网页（Next.js，设备 `:9090`）

沿用 `admin.css` 的 Cool Tech 体系，**颜色、圆角、阴影、焦点环一律引用 token，硬编码色值视为缺陷**：

- 画布 `--ds-bg` `#f6f8fb`，卡片 `--ds-bg-card` `#ffffff`，发丝边框 `--ds-border` `#e2e8f0`。
- 主色 `--ds-accent` `#0e7490` 承载对比（按钮、链接、激活文字）。
- 亮青 `#22d3ee` 在 `admin.css` 里有两个 token，用途不同，别混：**焦点环一律用 `--admin-ring`**（决定 6A），`--admin-glow` 留给浅色底和激活点。两者当前取值相同，但语义分开，改配色时不会一起动。亮青**不做白底上的文字或填充**。
- 字体 `--ds-font-display`（Outfit）与 `--ds-font-body`（DM Sans），数字一律等宽数位。
- 圆角 `--admin-radius-lg`（14px）用于卡片，`--admin-radius-md` 用于按钮。
- 移动优先：桌面左侧边栏，移动端底部 tab；**内容区桌面限宽 720px 居中**。
- WCAG AA 是底线：≥4.5:1、可见焦点、键盘可操作、控件有标签。

**命名**：产品名一律为 **CHILL**，设备上任何界面、以及 clash/ShellCrash 配置里都不出现 RELAX。
（注意：「线路与出口」是触屏磁贴的副标题，见第 3 节，不是后台的导航项名。）

**CHILL 页布局**：降级横幅（仅异常时渲染，整块浅色底 + 深色文字 + 右侧主按钮，不用彩色左边框）→ 状态条 → 地区卡片（固定两列，唯一使用卡片的区域）→ AI 出口 → 设备列表 → 订阅列表 → 高级（zashboard，第三方面板，新标签页打开）。

**除地区卡片外，其余五块用分节列表，不是卡片**（决定 4A）。状态条、AI 出口、设备、订阅、高级都按：小号组标题（`--ds-text-dim`）+ `--admin-divider-light` 发丝分隔线 + 内容直接贴 `--ds-bg` 背景，**不再各包一层 `SectionCard`**。地区卡片是唯一例外，因为点卡片就是切地区，卡片本身即按钮，保留 `--admin-radius-lg` 圆角、`--ds-border` 发丝边框、`--admin-shadow-sm`。手机上列表行占满内容宽度，设备名和 IP 要在一行里显示得下。

**两条容易被违反的约束**：

- zashboard **不嵌 iframe**（决定 7A），新标签页打开并带外链图标。嵌进来会出现浅色外框套深色内容的夹心感，手机上还会嵌套滚动。阶段一另需说明：`:9999/ui` 是 mihomo 自带的通用面板，不是 CHILL 的界面，风格不同是正常的。
- 设备与订阅的列表行**不随视口拉长**（决定 7B）。宽屏右侧留白是有意为之，不要用内容填满。

**控件语义**：地区 `role="radiogroup"` + `role="radio"`；设备绕行 `<button role="switch" aria-checked>`；AI 出口原生 `<select>` 或带 `aria-expanded` 的菜单；降级横幅 `role="status" aria-live="polite"`；可点区域 ≥44px。

## 6. 反面清单（两个平台都不要）

- 每块内容各包一张白卡上下堆叠（App 界面应当是布局，不是卡片马赛克）。
- 渐变背景、玻璃拟态、霓虹发光、渐变文字。
- 图标装在彩色圆圈里当装饰；三列等宽特性网格。
- 彩色左边框卡片。
- 全部居中对齐；所有元素同一个大圆角。
- 用 emoji 当设计元素（节点名里的国旗除外，它是数据）。
- 状态用大块彩色药丸；应当用点加文字。
