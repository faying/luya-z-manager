## 1. 通用原则（两个平台都适用）

1. **状态和原因永远是第一优先级**，可改的东西第二，明细（流量、连接数、日志）放最后。
2. **状态不能只靠颜色**。任何状态都同时有符号和文字：`●` 正常、`▲` 警告、`■` 停止。
3. **空状态是功能**。不允许只写「无数据」，必须给出原因和下一步动作。
4. **减法优先**。元素要为自己的像素负责，装不下就砍，不靠装饰填空。
5. **卡片只在卡片本身就是交互时使用**。纯展示的分组用标题加分隔线。
6. **英文措辞**（2026-10-01 L2 定，触屏、网页、核心、agent、告警短信同一套；词以 `docs/ui-glossary.md` 为准）：
   - 句首大写；页名是专名，和网页菜单一样用 Title Case（Band Lock、Speed Test）。专名原样：Wi-Fi、eSIM、Tailscale。
   - 标签、状态词不加句号。提示行只写一句，有动作时动词开头，不写 Please，句末不加句号。
   - 点名页面时直接写页名，不加引号，和术语表一字不差（Turn on mobile data in Cellular）。
   - 单位大小写不变：Mbps、MHz、dBm、GB、n78、B3；数值和单位之间一个空格，顶栏这类挤的地方照中文现在的写法。网页英文眉题会转大写，眉题里不放单位。
   - 时间 24 小时制 `14:32`；时长 `14h 51m`、`5 min`；相对时间 `3 min ago`；停更 `last update 14:32`；日期 `26 Sep`（短信定宽 `01 Oct 14:32`）。
   - 计数优先写成不分单复数的形式（`Devices 6`、`6 online`），自然句才用 `TRN`。
   - 英文告警短信整条 `[Luya-Z] 正文 (01 Oct 14:32)`，纯 ASCII，≤70 字符。
   - 测试查：句末没有句号、没有 Please、单位大小写对、不含中文（SSID、运营商原名这类白名单除外）。

## 2. 状态语义（跨平台，语义不可变）

| 语义 | 含义 | 符号 | 触屏取值 | 后台 token |
|---|---|---|---|---|
| 正常 | 代理运行中 | `●` | `.ok` `#5ec85e` | `--ds-success` |
| 警告 | 降级但网络可用、或有需要注意的偏差 | `▲` | `.warn` `#d98a00` | `--ds-warning` |
| 停止 | 代理未运行，需要人介入 | `■` | `.bad` `#d9534f` | `--ds-error` |
| 中性 | 用户主动关闭、暂停、上游不适合接管 | `●` 灰 | 主题默认文字色 | `--ds-text-dim` |

**颜色取值可以随平台变，语义映射不可变。** LVGL 版触屏若换色板，必须保持这四种语义的一一对应，否则同一台设备上两代界面会互相矛盾。

对比度要求：任何状态文字在所属背景上 ≥4.5:1。触屏要在 `body.dark`（`#15161a`）和 `body.light`（`#eceef1`）两套背景下分别验证。

完整的 15 行状态文案表（含 API 不可达、空列表、订阅失败、切换成功）在设计文档的「界面设计决定 · 2A」一节，实施时以那张表为准。

**状态历史保留 20 条**（决定 3A），两个平台共用同一份数据。超过 20 条丢最旧的。触屏底部只渲染最近 1 条，后台在「高级」区展开全部 20 条（带时间、状态、原因和关键数值）。历史为空时不渲染该行，不显示「暂无记录」。

数据来源是 `/data/chill/events.log`（落 `/data`，重启不丢；`chill.sh` 每次状态迁移追加一行，写入时截断到最后 20 行）：

```
2026-09-16T03:12:41 overheat cpuss=86 -> direct
2026-09-16T03:29:07 recover  cpuss=63 -> running
```

触屏底部那一行由它渲染成：`最近：03:12 过热暂停 · 03:29 已恢复`。
这份历史同时是温控阈值标定的依据——跑几天看实际触发次数，再回填 `CHILL_TEMP_HOT_*`，所以格式不要随意改。
10-29 起 core 的温控（`docs/designs/thermal-care.md`）也经 `/tmp/luyaz/heat` 请 chill.sh 降到 eco（`hot`）或直连（`critical`）；代理核心仍只归 chill.sh 管，这类降档日志写 `warm core=hot …`。

## 4. 触屏（LVGL，新设计）

Rust（`touch-ui/rs/`，经 `lvgl-sys` 用 LVGL 9.5），320×480，FreeType 渲染 CJK。继承第 2 节状态语义（颜色值换了，语义一一对应不变：正常 → okT / green，警告 → warnT / orange，停止 → badT / red，中性 → t3）和第 1 节通用原则。完整规格（色板和对比度、字号表、每个组件的尺寸、每页布局、状态表）在新设计的设计文档里，代码里的唯一实现是 touch-ui 的 `rs/ui/src/kit.rs`（组件）和 `rs/ui/src/theme.rs`（色板、字体角色）。页面只能用这两处的东西，不自己设颜色、圆角、字号。

**主题**：浅色 / 深色 / 自动（`ui.conf` 的 `appearance`，自动按设备当地时间 19:00–07:00 深色，只在息屏时切换）。一个进程只用一套主题，切换 = exec 自己（进程号、进程名不变）。所有颜色已经按 565 量化并逐一算过对比度；调淡一律用 t3，不降透明度；鲜艳色（green / orange / red / blue）只放在没有文字的地方，带白字的地方用 fill 色。**开关例外**：开着的鲜艳绿轨道在白底上只有 2.2:1，开关状态靠圆钮左右区分（通行做法），颜色只是辅助。

**字体**：数字 Nunito（600/700/800，挂中文字体兜底；缺失时退设备 Roboto），中文设备 ZTEZhengYuan（常规 11–15，合成粗体 15/17/20/22/24，需要 LVGL 补丁）。最大字号 36（测速结果）；首页状态卡的结论句用 cj24b。最小：电池数字 10，数值标签 11，辅助信息 12。

**组件**（尺寸以 `rs/ui/src/kit.rs` 为准）：顶栏 26（时间 · 5 个信号点 · 制式 · 速率 · ▲ · 电池，速率放不下时依次换更短的写法）；浮动 tab 44（只在五个顶层页显示）；二级页标题栏 62（含顶栏，实底，圆形 ‹ 返回）；卡片圆角 20、外边距 10；列表行 40 / 两行 50，分隔线从 x=14 开始；分段按钮 30；开关 44×26；磁贴 145×78，一律白底，「开着」（CHILL 运行中、WiFi 开）= 副标题前一个绿点 + 绿字，不整块填色（整块蓝看起来像一直被选中）；状态块 72（卡片顶部，圆角 20 加一块方形补底）；底部面板圆角 22。按下：一档加深（深色主题一档变亮），松手恢复；透明底的列表行按下时铺一层 `track` 底色（只加深透明底等于没反应，2026-09-25）。动画只有两处：底部面板 180 ms 升起、二级页 150 ms 推入，`UI_ANIM=0` 全关。热区不小于 40×40。

**屏幕黑着时，手指点不到任何东西**：按电源键关的屏，触摸完全无效，只有电源键能亮；自动息屏的，双击亮屏（单击、滑动、两下离得太远都不算，防口袋误触）。叫醒屏幕的那个动作（双击，或按电源键时手指正按着）不算点击，亮屏后 300 ms 内也不接收点击。规则在 `touch-ui/rs/ui/src/logic.rs` `ui_tgate_step`，有单测和渲染测试。

**长文本**：数值完整显示，名字用剩下的宽度并在末尾 `…`；IP、ICCID、IMEI 不截断。注意 LVGL 9 的 `…` 模式需要固定高度（`uk_label_w` 已处理），否则会换行。

**状态**：每个颜色状态都另有文字线索（信号良好 / 偏弱 / 没有信号、运行中 / 已关闭、直连 / 中继 / 离线、▲）。充电只把电池变亮绿（用户选定，和设计图一致，不加闪电）。空状态和出错状态写具体文案和下一步（状态表见设计文档）。数据服务掉线 ≠ 没信号：状态块变灰，写「数字停在 hh:mm」，数值调淡但保留。

**事故（顶栏 ▲，2026-10-24「变差才通知」）**：▲ 有两个来源——未读告警，和 core 在新鲜数据里说开着的事故（`regress` 块；块过期或 core 没声音时不因事故而亮）；告警通道失联照旧红色。点击范围 44×44，左缘贴速率的点击范围右缘，往右盖过 ▲ 和电池（不压速率）；`luyaz-ui --hitcheck`（rs/hitcheck.sh）逐页打开，任何可点元件有五分之一以上在它底下就算失败（所以「网络诊断」的「再查一次」放在页面里，不在标题栏）。点它打开「健康与告警」，最上面「事故」区：开着的（≤5，多了写「还有 N 个开着」）和 24 小时内结束的（≤3；跨开机只按可信墙钟算）；两行（▲/● 名称 · 还开着 / 已恢复 / 已结束 · N 次；14:32 起 或 03:12–03:29，出口另写 CHILL / Tailscale）加一行可选的 12 号 t2「同时观察到」；列不可点（详情在网页）。块过期：保留最后的列，t3，标题下「事故数据停在 hh:mm」；从没读到：「读不到事故数据」；旧 core：「core 版本太旧，不支持事故」——一律不隐藏。

**首页层级**（2026-10-24 评审，取代 2026-09-24 的「结论优先 + 双磁贴」）：第一屏一眼回答三件事：网络现在什么状态、我现在什么处境、要不要做什么。四个固定版位；内容只在版位里变，不会把下面的版位挤走：

**摆放模式**（蜂窝 › 排查；用户 2026-10-24 评审，样稿 v1–v10 在 iCloud `u60-design-review/2026-10-24-摆放模式/`，公式和依据在 `docs/designs/travel-assist.md` §8）：一个分数回答「这里好不好」，拿着设备走动看它变。设备没有罗盘和运动传感器，所以不说方向、不编地名：地方叫「第 N 处」，加记下的时间。
- **分数** 0–100 = 这条链路最快速度的几成（touch 1.13.4 起）：3GPP TR 36.942 附录 A.2 的 SINR→吞吐量曲线（0.6·log2(1 + SINR)，−10 dB 起算，4.4 b/s/Hz 封顶，约 22 dB 满分，处处连续）× 频宽折扣（主载波自己的 MHz：SA 是 NR 小区，4G 是 LTE 小区，NSA 是锚点 + 5G 那条；辅载波不算，基站只在下载时才加上；÷ 这次看到过的最宽，速度跟频宽成正比，TS 38.306 §4.1.2）。RSRP、RSRQ 不乘进去（SINR 已含噪声和干扰，也没有公开模型），只用来说原因。SINR 先按约 3 秒平滑，读数一跳分数是滑过去。分级：≥ 80 很好（约 18 dB），≥ 60 良好（约 13 dB），≥ 40 一般（约 8 dB），其余差。两处差 8 分以内算一样。
- **状态卡**（按结论染色，同首页，198 px）：左边结论 cj22b，右边分数 Nunito 36（记录中换成 acc 色倒数「5 s」），下面两行 13 px（先说怎么做，走动时「比 5 秒前 +8，继续往这边」；再说为什么：扣分最多的一项和读数，如「差在干扰：SINR 9.6 dB，转个方向或靠窗」，80 分以上「干扰低、信号强、基站不忙」），底部 126 px 是近 3 分钟分数走势，写法同首页网速波形（填色面积 + 3 px 线，用结论色）；每个记下的地方是线上记录那一刻的 20 px 圆圈（里面是序号，最好的实心），最好的再加一条 1.5 px 横线。
- **分数卡**（66 px）：五格，每格「数字（Nunito 20）· 名称 · 意思（11 px）」：总分（= 大字，下面写很好／良好／一般／差）｜竖线｜SINR（dB，下面「77 分」）· 频宽（MHz，下面「扣 62」或「不扣」）· 信号强度（RSRP，下面正常／弱，≤ −105 橙色）· 基站负载（RSRQ，下面不忙／忙，≤ −15 橙色）。总分 = SINR 得分 − 频宽扣；强度和负载已含在 SINR 里，不另扣（用户 10-25：总分放第一格，每个子项有自己的位置；两个数字配两个字看着奇怪）。不用条形图。NSA 的信号质量只读 4G 锚点，5G 那条只加频宽。
- **记录**：三格，同首页底排（第 N 处 · 14:03 / 分数 / 最好 · 也行 · 低 N · 差不多）；最好的浅绿底；空格只描边，下一格写「下一处」。记第 4 处时丢掉最早的非最好那处。
- **来回切基站**：在当前这一处（记一处就重新算），2 分钟内切回刚离开的小区 ≥ 3 次，并且分数 < 60，才说「卡在两个基站之间」，并写出是哪两个小区（3GPP 的乒乓切换；小区按 PCI 认，不带频段，因为载波聚合时 PCI 会报在别的载波频段下；PCI 65535 的读数不算）。这时优先于其他结论；记录时切过基站的那处标「切过基站」，除非每处都切过，否则不选它当最好。分数一样的几处选后记的那处。
- **结论**：还没记 = 按分数（「这里可以放」/「这里一般」/「这里信号差」）；记录中 =「正在记第 N 处」（8 秒，手拿开，「取消这次」）；两处以上 =「放回第 N 处」（现在跟最好差 5 分以内则「就放这里」），全部差 5 分以内「放哪都差不多」，最好的也不到 30「放哪都不行」（按钮「换个房间再记」），分数一样且主要被负载折扣拉低「不是摆放的问题」（按钮「去测速」，打开测速）。
- **往下滑**：这次最好 · 对比 · 在用（频段 · PCI）、重新开始，以及「换了小区会标出来；这页开着不息屏」。

各部分的说法：
- **网络标签**：和手机状态栏一样简短，顶栏和状态卡顶行都用它。由 `ui_net_label()` 根据原始制式和在用载波数算出来：
  - **2G**：GSM、GPRS、EDGE、CDMA 1X。
  - **3G**：WCDMA、TD-SCDMA、CDMA2000（EV-DO、eHRPD）、HSPA。**3G+**：HSPA+、DC-HSPA+。
  - **4G**：LTE、4G、FDD-LTE、TD-LTE，单载波。**4G+**：LTE-A、LTE_CA、4G+，或在用 ≥2 条 LTE 载波。
  - **5G**：SA 或 NSA，1 条 NR 载波。**5G+**：在用 2 条 NR 载波。**5G-A**：在用 ≥3 条 NR 载波，或原始值本身写着 5G-A。模组没有 5G-Advanced 的明确标志，这里是按国内运营商常见的三载波聚合推断的。
  - **状态卡顶行**不重复顶栏的简写，而是写更细的一层：「5G SA」「5G NSA」「4G LTE」「3G WCDMA / HSPA+ / CDMA2000 / TD-SCDMA」「2G EDGE / GPRS / GSM / CDMA 1X」（`ui_rat_long()`）。
- **载波**：先写解读，下一行才是每个在用载波的频段和带宽。总带宽只算在用的载波。组网方式已经写在顶行，这里不再重复。解读的写法：
  - 5G SA 和 4G：「N 条载波聚合 · 带宽很宽/充足/一般/偏窄」，只有一条时写「单载波 · …」；
  - NSA：「4G 锚点 + 5G，N 条载波 · …」；
  - 3G 和 2G：「这个制式没有载波聚合」。速度的影响写在提示行里，载波块不再重复。
- **信号评价**：「信号很好 / 良好 / 一般 / 较差」，主要看 SINR，RSRP 太低时往下压一档。
- **频段**：频段号写成 B3 / n78。「GSM 900」「DCS 1800」这类是频率，保持原样。
- **4G 不做载波聚合时**：服务小区只在 `lte_*` 字段里，要从那里补出来，不能显示「无载波」。

渲染测试的场景：good、weak、nosignal、core-down、loading、nosim、abroad、lowbat、full-charging、long-names、empty、nsa、lte、3g、nodata、5ga、edge，每个场景都有深色和浅色两种主题。

**首页载波**（载波明细卡）：先放服务小区（`nr_band/nr_bw/nr_rsrp/nr_pci/nr_channel`），再把 `nrca`/`lteca` 每一组原样追加（服务小区在里面会以 -140 地板值再出现一次，这是 modem 报的配置载波，不去重）；未激活载波压成一行 t3。

**会改设备状态的控件一律两段确认**：第一次点变 fillOrange「再按一次确认」，5 秒内再点才真下发（选网方式、应用锁频、恢复默认、eSIM 切换、切换原厂界面、删除短信、关闭 CHILL）。WiFi 开关例外。

**每一次点击都要当场看得见**（2026-09-25，用户在「情景 · 网络」页点了没反应）：
- **第一下**在回调里当场重画，不等 1 秒的刷新。按钮变 fillOrange；列表行整行铺 `washW` 浅黄底，右侧「再点一次确认」，卡片底下一句写这次会发生什么（例：「切到「外出」：Wi-Fi 开着 / 之后一直固定，点「自动」才恢复」），分两行时主动换行，不让一个字掉到第二行。
- **单选列表**（情景、选网之类）用单选圈：实心 = 现在真正生效的那一项，不是「刚点的那一项」。
- **点了已经生效的选项**说一句（「现在已经是自动 · 判断为「在家」」），不静默忽略；忙的时候点也说一句（「正在切换，稍等」）。

- **被拒**的原因写在这张卡片里，不只写在页顶。

**没有数据源的功能写明缺什么**：邻小区 / MIMO / BLER 本机拿不到（没有 `/modem/latest-signals`），页面写原因，不画空壳。

**事务（写操作层，E4，设计 `docs/designs/write-op-layer.md` DD3、DD5、DD9、DD12、DD13、DD16）**：凡经核心的写（现在是网络模式），文字全部由核心随 `op` 块发（`say/next/note/what/source/old/target`，各带 `_zh/_en`），触屏只排版；词表在 `docs/ui-glossary.md` §13。
- 首页和对应设置页（蜂窝 › 网络模式）用现有状态块显示，不另叠进度卡；其他标签和二级页在标题栏下放一行**事务行**「正在换制式 · 1:42 ›」（整行 ≥40 高），点了开**事务页**。
- 事务页五层：结论 → 「旧 → 新 · 来源 时间」→ 三行进度（设置已生效 / 已注册 / 数据，✓ 或 …）→ 倒计时（「1:42 后没通就退回到 X」；自动退回没开时「还剩 0:48 · 自动退回没开」）→ 按钮。核心推送 20 秒没更新：倒计时调灰写「停在 1:42 · 等设备响应」，不再跳。
- 按钮写具体值：「退回 X」主按钮在左，「保留 Y」次按钮在右；都两段确认，同一时刻只有一个待确认，待确认是 fillOrange 加一句后果。到点以设备为准，待确认作废；退回进行中只显示进度、没有按钮。
- 结束后事务行变成结果行（「▲ 没通 · 已退回自动 ›」），3 秒类（已切到、已退回、不需要确认）只在亲眼看到它结束时显示；常驻类留到点「知道了」（经核心只记账，触屏和网页一起收起）。退回也没通（DD9）红色占状态块，写现值和上次确认值，按钮「再试一次退回到 X」「重启设备」。
- 系统 › 改动记录：一条两行（「制式 · 自动 → 只用 4G」/「10-03 14:32 · 网页 · 已切到只用 4G」），点开详情，撤销/重做在详情里；不能撤的变灰写原因。
- 数据服务卡住（20 秒不动）：经核心的写控件提前变灰并写「数据服务没响应 · 暂时不能改设置」。忙（别的写在跑）不提前变灰，点了写核心回的那句。

**测速页**（测速 v2，`docs/designs/net-performance.md` DR1–DR13；用词见 `docs/ui-glossary.md` §17）：数字先，结论紧跟。结果卡：n36 多连接稳定段；一行 cj17 结论，字来自 core（「▲ 慢在单连接、下载时卡」，最多两个层名，再多写「等 N 处」；没有就「● 没发现瓶颈」）；↑ 和延迟（「延迟 23 ms，下载时 210 ms」）；服务器 · 连接数 · 用掉多少；「也测经 CHILL」开关行（默认关，每次测完回到关，CHILL 没在跑或漫游时变灰并写原因）；按钮，下面一行流量上限。卡片下面是「分层」展示区（标题 + 分隔线，不是卡片）：五行层行，顺序固定——单连接、代理、下载时卡、无线、基站、Wi-Fi——写法同诊断页层行（● ▲ 带状态色，没测整行灰并写「没测 · 原因」，行高 40）。只有代理行（▲ 时，去出口页）和无线行（SINR < 3，去找位置页）可点，整行都是点击区，右侧「›」。测着：右上角阶段字带步数（「3/5 · 多连接下载」；开经 CHILL 共 6 步；找节点不计步），大数字是实时速率，结论行位置写测法；「分层」测完才出现。样本不足：数字 t3 灰，「▲ 样本不足，数字只供参考」，不显示分层。粗测（诊断或漫游）：数字正常色，「● 粗测 · 漫游中只测 5 秒」，不显示分层。漫游：多一行 t2 提示，第一下只把按钮变成「走漫游流量，再按一次」。接旧 core（没有 `method_version`）页面完全照旧；不做历史列表，不做旧测法标记。

**回归测试**：`touch-ui/rs/build.sh test`（单测，含渲染的文字/字形/几何检查）；改页面后用 `touch-ui/rs/still.sh` / `scripts/screenshots/touch.sh` 在视图模型上看，并在设备屏幕上确认。和 C 版渲染测试逐像素比对的 `parity.sh` 及其视图模型 2026-10-21 已退役，新的视图模型以后从 Rust 触屏生成。

**已知踩过的坑**：
- `LV_USE_STDLIB_MALLOC` 曾经设成 `LV_STDLIB_BUILTIN`（LVGL 自己划一块跟系统内存完全隔离的小内存池，从 128KB 一路加到 2MB 都还在崩），根因是这个隔离本身——litehtml 版（旧 C 触屏）直接用系统 `malloc()`，面对的是整机 690MB+ 可用内存，从不出这个问题。已经改成 `LV_STDLIB_CLIB`（真正的系统 malloc/string/sprintf），跟 litehtml 版走同一条路，`LV_MEM_SIZE` 相关配置全部移除（只对 BUILTIN 模式有效）。**这条是真正修复，之前"减少不必要的 `lv_label_set_text` 调用"那版只是缓解，不是根治**——但那个优化本身仍然保留，两个问题不是互斥的。
- `lv_label_set_text()`/`_fmt()` 无论新文字是否跟旧文字完全相同都会整个释放再重新申请一次文字缓冲区——每次 `refresh_cb` 刷新前先跟缓存对比，值没变就跳过调用，不要无条件每秒重设几十个标签的文字。
- 验证真机稳定性只能用"真的去读一次 `/tmp/luyaz/dumpfb` → `/tmp/fb.dump`，确认字节数正确"这种功能性检查，`pidof` 查得到进程不代表进程真的还在正常跑主循环（LVGL 断言失败是死循环不是真的退出，`pidof` 会一直查到它）。
- `lv_slider`/`lv_button`/`lv_switch` 的构造函数默认都打开 `LV_OBJ_FLAG_SCROLL_ON_FOCUS`（配合 `lv_obj.c` 里 `LV_EVENT_FOCUSED` 的处理），某个控件在页面构建期间一旦被 focus，会自动把自己滚动进可视区域——这个项目从头到尾只用触屏，没有 group/keypad 场景，focus 驱动的滚动毫无意义，但默认值就是开着的。表现是某个页面第一次构建时莫名其妙停在滚动到一半的位置（首次访问「系统」tab 看到的第一张卡是「电池与负载」而不是最上面的「屏幕」），之后再切进来又正常，容易被当成偶发问题。凡是用 `uk_scroll` 的页面，构建函数末尾都加一行 `lv_obj_scroll_to_y(t, 0, LV_ANIM_OFF)` 钉回顶部——这行只在页面构建时跑一次，不影响用户之后自己滚动的位置。
- **字体和字形必须配对**：`LV_SYMBOL_*`（LVGL 私有区码位）只能放 montserrat 标签（改版后只剩功能图标和 ✓）；中文、`·`(U+00B7)、`↓↑`(U+2193/2191) 放 CJK 字体或挂了 CJK 兜底的 Nunito（`UF.*`）。放反了两边都是豆腐块——2026-09-21 一轮截图里同时出现了两种：Tailscale 的 IP 行用 montserrat 拼 `·`、图表网速标题用 FCN_S 拼 `LV_SYMBOL_DOWN`。数字/ASCII 放 CJK 字体没问题，所以拿不准就用 FCN_S。另外 `LV_SYMBOL_DOWN`/`LV_SYMBOL_UP` **画出来是 ∨ ∧ 折角，不是 ↓ ↑ 箭头**，看着像"展开/收起"而不是上下行速率——顶栏和图表的速率一律用 FCN_S + 真正的 `↓`(U+2193) `↑`(U+2191)，跟现役 litehtml 版状态栏保持一致。
- **montserrat 标签里绝对不能出现中文**，会渲染成豆腐块方框。这个坑 2026-09-18/09-21 一共踩了四次（网络页 PLMN 行、Tailscale 状态"已连接"、载波子卡片的"未激活"后缀、WiFi 密码行的"密码未公开"）。判断标准不是"当前这个值是不是中文"，而是"这个标签**有没有可能**取到中文值"——包括兜底文案和状态词。数字/ASCII 放中文字体反而没问题，所以拿不准就用 `UF.cj*` 或 `UF.n*`（Nunito 挂了中文兜底）。
- `lv_tileview_add_tile()` **不会**设置 tileview 的"当前 tile"指针，`tile_act` 一直是 NULL，直到第一次 `lv_tileview_set_tile*()` 或第一次滚动结束（`lv_tileview.c:92,181`）。所以刚启动时虽然首页明明就在眼前，`lv_tileview_get_tile_active(tv) == s_tiles[0]` 却是 false，所有靠这个判断做可见性门控的轮询（Tailscale、eSIM）一次都不会跑——表现是首页 Tailscale 卡片永远空着，要翻到别的页再翻回来才有数据。`ui_create()` 建完 tile 后必须补一次 `lv_tileview_set_tile_by_index(tv, 0, 0, LV_ANIM_OFF)`。
- **ui_create() 里任何"把界面恢复到初始状态"的调用，都要能在控件还没建完时安全返回。** 2026-09-21 重构时 `sub_close()`（收起二级页层）顺手调了 `update_tabs()`，而 tab 栏是在它之后才建的——`lv_obj_set_style_text_color(NULL, …)` 直接段错误，进程启动即死。因为侧载测试时正式 UI 已经被 kill，厂商看门狗发现没有 UI 在画，把**整机重启**了（本项目第二次这类事故）。两条应对：受影响函数开头加 `if (!s_tabs[0]) return;` 这种建成检查；测试启动脚本改成**起不来就自动回滚**——日志写 `/data/lvgltest.log`（不是 `/tmp`，RAM 盘会被重启擦掉，正好丢掉解释崩溃的那份日志），起 8 秒后 `grep "first refresh done"`，抓不到就立刻 kill 并 `sh start.sh legacy` 拉回正式 UI。`ui_create()` 里几个 `fprintf(stderr, "ui: …")` 面包屑就是给这个检查用的。
- 侧载测试前点亮屏幕不要无脑按电源键——那是 toggle。先读 `/sys/class/leds/led:lcd/brightness`，是 0 才按；否则会把亮着的屏幕关掉，`backlight_is_on()` 变 0，所有靠它门控的轮询（Tailscale/CHILL/eSIM/WiFi 开关状态）全部读不到数据，截图看起来像布局 bug。
- 轮询门控里的 `backlight_is_on()` 在息屏时是 0，headless 截图验证（SSH + fb-dump，不碰屏幕）会让这些卡片一律空着，看起来像布局 bug。验证前先用 `touchsim /dev/input/event0 key 116` 点亮屏幕（自动息屏设为"常亮"时，UI 自己永远不会开背光，只有电源键会）。

## 5. 后台管理网页（设备 `:9090`）

本节只写**行为和视觉**，跟用什么框架无关（Phase 8，T19）：现在的 luyaz-web 和以后的重写都照这一节。用词「页族」「三档写操作」见 `docs/ui-glossary.md` §15。现在这版的文件和组件名集中在本节末尾「当前实现」。

2026-09-24 整体改版，视觉语言取 **Cohere + Figma**（参考文件和设计、工程评审记录放在仓库外，是维护者的工作笔记）。触屏仍用第 4 节自己的配色，网页**不再镜像** `touch-ui/rs/ui/src/theme.rs`。旧的 Cool Tech（`admin.css`、Outfit/DM Sans）已删除。

**颜色只经 token**：一律用 `--nd-*` 这套 CSS 变量（名字不随框架变），页面里出现十六进制色值视为缺陷。token 只在一处定义；改了 token 必须重跑对比度检查，要求全部通过（文字 ≥4.5:1，非文字 ≥3:1）。

**画面**

- **纸面 + 墨色**：画布暖白 `--nd-bg` `#fafaf8`，卡片白色，外圈 1px 发丝线 `--nd-hair`，不用阴影（只有浮层：弹窗、提示、⌘K 有阴影）。正文墨色 `--nd-t1` `#17171c`，次级 `--nd-t2` / `--nd-t3`。
- **一个主色面**：`--nd-primary` 近黑（深色模式为近白）。主按钮、分段选中、多选标签选中、开关打开、侧栏以外的"选中"都用它。每屏只放一个主按钮，其余降为次按钮（白底发丝线胶囊）或文字按钮（下划线）。
- **颜色只表示状态，不表示分类**（2026-10-31，取代按页族配色块）：状态块正常或中性时就是普通白卡加发丝线，和其他卡一样；只有注意 `--nd-washW` 琥珀、出错 `--nd-washB` 珊瑚才铺底色。侧栏当前项、手机底栏当前图标用中性色阶 `--nd-accS` 配墨色。首页模块卡（CHILL、情景、Tailscale）是普通卡片。根元素上的 `data-family` 照留（页族分组），但不再决定颜色；`blk*` 色值不再使用。色块里的文字一律是墨色，只有状态符号带语义色。
- **深绿色带（Cohere）**：只用于登录页，`--nd-band` `#003c33` + 白字。
- **告警条**：不是色块，是一行墨色横条（Cohere 公告条），手机上只一行，宽屏再带详情；避免和状态块叠成两块彩色。
- **深色模式**：同一套角色，色块换成饱和的深色调（不是发灰的暗色），主色面反白；告警条在深色下是抬高的深色条，不反成白块；深色终端带（AT、日志、进程）两种模式都是深色。
- **图表线**用独立的 vivid 色（`--nd-green/orange/red/blue`），不跟着单色化。

**字**

- 拉丁字母和数字用 **Geist** 加等宽数字，IP、IMEI、PCI 这类数据也一样；**Geist Mono** 只用于真正的代码（终端色带、AT 终端、十六进制、原始查询），中文走系统字体（PingFang 等）。中文只有离散字重，所以只用 400 / 500 / 600，不用 700/800。
- 中点 `·` 只用来隔开数据（`100 MHz · −97 dBm`）；成句的文字用正常标点（「使用电池，约可用 49 小时」「2 条新告警：Wi-Fi 掉了」）。不重复页面上方已经写过的内容（标题下已有运营商、旁边已有格数读数）。ⓘ 只给术语（RSRP、PCI、ARFCN），不给「频段」「带宽」这种平常词。
- 手机优先，≥1024 再大一档：页面标题 22 → 28，正文 15 → 16，辅助 13 → 14，状态块标题 17 → 20，读数 28 → 40（首页主读数 44 → 64）。
- **输入框不小于 16px**（iOS 小于 16 会在聚焦时放大页面）。
- 分组标题是**正式标题**：正文字体，15 → 16px，600，墨色，不转大写、不加字距（2026-10-31 起不再用灰色等宽小号眉题）。读数标签、对话框说明标签、侧栏锚点也用正文字体，不用等宽、不转大写。
- 标题、状态、模块标题用 500，靠字号和字距拉开层次，不靠加粗；600 只给小标题 `<h3>` 和选中项。色块里的状态词是墨色，只有符号带语义色；色块里最浅的灰自动提到 `--nd-t2`。

**形**

- 圆角：卡片 12、面板 16、输入框和选项 8、按钮与分段为胶囊。
- 可点区域始终 ≥44px：缩小的是字和内边距，不是点击区。开关视觉 40×24，点击区 44×44；分段视觉 30 高，点击区 44。

**结构（改版时定的，不要回退）**

- 导航：<640 底部四个标签（首页 / 图表 / 功能 / 系统），640–1023 左侧图标栏，≥1024 240px 侧栏带分组；⌘K 搜索全部页面（中文、拼音、别名）。页面表（路径、页族、标题、搜索别名）只在一处定义，导航、⌘K、页族都从它来。
- 每页顺序：标题 → 状态块（状态 · 原因 · 下一步 · 新鲜度）→ 可改的东西 → 明细。设置页限宽 720，看数页可两栏。
- **三档写操作**：第一档直接发；第二档页面内确认（写明后果）；第三档弹窗（发生什么 / 断开多久 / 怎么恢复，远程访问时加 Tailscale 警告，恢复出厂要输入「恢复出厂」）。每个写操作之后读回验证，读不回就写「设备已接受」而不是「成功」；多步写逐步显示，失败只重发没完成的步骤。每个控件属于哪一档有一份清单；改控件先改清单。
- **事务**（E4，设计 `docs/designs/write-op-layer.md` DD4、DD5、DD8、DD15）：经核心的写（现在是网络模式）不再自己读回，交给设备确认；文字照核心的 `op` 块显示，词表在 `docs/ui-glossary.md` §13。
  - 外框横条（沿用告警条样式，`role=status`，退回失败 `role=alert`）：每页都有，进行中「正在确认 · 1:42」，≥640 加「制式 · 旧 → 新 · 来源」；点「详情 ›」去对应页，在对应页上不显示。倒计时 `aria-hidden`，只在阶段变化时念。
  - 对应页的状态块换成事务状态：同触屏五层，按钮「退回 X」「保留 Y」是第二档页内确认；手机上竖排、占满宽、≥44px。
  - 系统 › 设备 › 改动记录（`/changes`）：同触屏的两行；详情里撤销，会断蜂窝的（网络模式）第三档，其他第二档；每次发新的 `op_id`，绝不重发。设置页底部「上次改动 14:32 · 触屏 ›」链到那条（现在只有网络模式）。
  - 数据服务卡住：横条写「数据服务没响应」，经核心的写变灰；改动进行中网页断线：横条写「和设备断开了 · 操作结果未知」，不自动重发，连回来照常显示结果。旧核心（`/api/ops` 的 `supported:false`）：没有横条和改动记录，写操作照旧读回。
- 数据停更时保留旧值、变灰、写「N 分钟前」，不清空成 0。
- 图标用 Phosphor：选中和磁贴实心，其余粗线。

**命名**：产品名一律为 **CHILL**，任何界面和 clash/ShellCrash 配置里都不出现 RELAX。

**CHILL 页的两条约束**（沿用 2026-09-16 决定 7A、7B）：zashboard **不嵌 iframe**，走 `:9090/chill-ui/` 反代在新标签页打开；设备与订阅的列表行不随视口拉长。

**控件语义**：地区 `radiogroup` + `radio`；开关 `switch`；分段为单选的 toggle 组；告警条 `role="status" aria-live="polite"`；弹窗有标题和描述，关闭后焦点回到触发按钮。

**实时数据**（换成推送以后也一样）：数字变了只换数字，不重排、不闪；正在输入的框、展开的详情、待确认的操作不被新数据冲掉（DR12）；读屏只念结论和告警的变化，不念每次刷新的读数（DR13）。

**当前实现（luyaz-web）**：token `crates/luyaz-web/static/nd/newdesign.css`；组件样式同目录 `nd.css`、`shell.css`（`src/assets.rs` 拼成一份）；对比度 `node crates/luyaz-web/tools/contrast.ts > docs/web/contrast.md`；页面表 `crates/luyaz-web/src/routes.rs`；事务条与写确认 `crates/luyaz-web/src/opbar.rs`、`crates/luyaz-web/templates/components/write.html` 及核心事务表 `crates/luyaz-core/src/ops/spec.rs`；e2e 测试 `crates/luyaz-web/e2e/`；档位清单 `docs/web/controls-inventory.md`（其中三档分级规则有效）。换实现时改这一段，上面的规则不动。

**测速页（/tools/speedtest，测速 v2）**：顺序同触屏（数字 → 结论 → 分层）。状态区原因行写结论（「完成 · ▲ 慢在单连接」），测着时写「3/5 · 多连接下载」；只播报换步和结论，不播报百分比和实时数字（DR13）。结果墙仍是 4 格：下载（多连接稳定段，大格）、上传、延迟（空闲）、下载时延迟（取代抖动）。结果墙和「测速来源与节点」之间是「分层」`<ul>`，行同触屏，● ▲ 有文字等价；代理行链到 CHILL 页。详情加全程均值、抖动、连接数，和只读的「内核调参：开 / 关」（取自结果的 `net_tune`）。「也测经 CHILL」开关在来源区，规则同触屏。行内确认写这次测速的费用（30 秒 / 750 MB；经 CHILL 40 秒 / 1.15 GB；漫游那一句）。接旧 core 时页面不变。

## 6. 反面清单（两个平台都不要）

- 一个指标一张卡，上下堆成马赛克。卡片**只允许**两种用法：分组列表（一张卡里一组同类的行），和整块可点的模块（首页情景 / CHILL / Tailscale 卡、功能磁贴）。
- 渐变背景、霓虹发光、渐变文字、真模糊（网页顶栏和底栏的轻微背景模糊除外）。触屏的「染色玻璃」只用在浮动 tab、返回键、底部面板、标题栏右侧按钮上，而且是不透明实色。
- 图标装在彩色圆圈里当装饰；三列等宽特性网格。
- 彩色左边框卡片。
- 全部居中对齐；所有元素同一个大圆角。圆角分档是有意的：触屏面板 22、卡片和磁贴 20、选项 14；网页面板 16、卡片 12、输入框和选项 8；胶囊为半高。
- 用 emoji 当设计元素（节点名里的国旗除外，它是数据；触屏上转成国家码显示）。
- 状态用大块彩色药丸；应当用点加文字。选中项的填色胶囊（分段、频段、出口选项）不算状态药丸。
