## Design Context

### Users
The web dashboard (`web/`, Next.js static export served by the on-device Rust agent on `:9090`, LAN-only) is used to administer a **ZTE U60 Pro 5G CPE router** running OpenWrt. Primary user is the device owner — technically literate, comfortable with dense status data — but the UI is **also shared with other U60 owners / the community**, so it must stay approachable and not assume insider knowledge. Jobs to be done: configure Wi-Fi (incl. the new Home Mode SSID auto-off), mobile network/APN/band lock, SMS, monitoring (signal, battery, temp), and system/services. Often used on a **phone or tablet on the same LAN**, not just desktop.

### Brand Personality
Confident, utilitarian, calm. Three words: **clear, trustworthy, unfussy**. It should feel like a precise instrument panel — information-dense but never noisy. No marketing flourish; every element earns its place. Emotional goal: the user feels *in control* of their device.

### Aesthetic Direction
**New design, Cohere + Figma** (2026-09-24; tokens in `web/src/app/newdesign.css`, components in `web/src/components/nd/`). Full rules are in `docs/DESIGN.md` §5; the short version:
- Warm paper canvas, white hairline-ruled cards, ink text; no shadows except floating layers.
- One primary surface (near-black pill, white in dark mode) for the primary action and every "selected" state.
- Colour comes from flat Figma colour blocks, one per route family (charts blue, network lime, Wi-Fi mint, services lilac, SMS pink, system cream), used by the status block and the current nav item; warn/bad keep amber/coral. Home and login use Cohere's deep-green band `#003c33`.
- Geist + Geist Mono for Latin/data, platform CJK face for Chinese, weights 400/500/600; mono uppercase eyebrows for section labels. Phone type one step smaller than desktop; inputs stay ≥16px.
- Light and dark themes, following the system unless chosen in Settings.
- **Anti-references**: the "AI slop" look — gradients, neon glows, glassmorphism, iOS-style grey canvas with rounded white cards, blue everywhere, identical icon+heading+text card grids.

### Design Principles
1. **Tokens, never hard-codes.** All colour/radius/shadow come from the `--nd-*` variables or their Tailwind utilities (`bg-nd-card`, `text-nd-t2`, …). A raw hex in a page is a defect; rerun `scripts/contrast.ts` after any token change.
2. **Information density with rhythm.** Dense status data is fine, but group it with varied spacing and hairline separators — not walls of identical cards.
3. **Mobile is a real target.** Layouts must work on a phone on the LAN: no horizontal scroll, ≥44px touch targets, controls reachable one-handed. Adapt, don't amputate.
4. **WCAG AA is the floor.** ≥4.5:1 text contrast, labelled controls, visible focus, keyboard operability, semantic structure.
5. **Quiet confidence, confident colour.** Chrome stays ink-on-paper; colour arrives as whole flat blocks (the status block, the home module cards), never as tints sprinkled on every element. Status is always symbol + word (`StatusMark`), never colour alone.
