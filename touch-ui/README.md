# Luya-Z Touch UI

**English** · [中文](README.zh-CN.md)

Part of **Luya-Z**: an open-source replacement UI for the 3.5-inch front-panel touchscreen of a 5G portable hotspot. Written in Rust + LVGL + FreeType, it draws straight to DRM/KMS, reads touch through evdev, and builds as one static aarch64 binary (`luyaz-ui` on the device) that runs independently of the stock UI.

> **Hardware:** runs on the ZTE U60 Pro (MU5250). Community project, not affiliated with ZTE. Use at your own risk.

## Where it lives

The touch UI is the `touch-ui/` folder of the [luya-z-manager](https://github.com/faying/luya-z-manager) repo; its Rust crates are members of the manager Cargo workspace. The old standalone `luya-z-touch-ui` repo is superseded and no longer updated.

| Component | Source | Role on the device |
|---|---|---|
| **luyaz-ui** (this folder) | `touch-ui/rs/` | Front-panel touch UI |
| luyaz-core | `crates/luyaz-core` | Local backend at `127.0.0.1:9460`: `/v2/state`, SSE `/v2/events`, `/v2/screen`, write actions under `/v2/api/...` |
| luyaz-web | `crates/luyaz-web` | Admin web on `:9090` |
| luyaz-sentinel | `crates/luyaz-sentinel` | Screen owner and watchdog (control FIFO `/tmp/luyaz-screen.ctl`) |

```
luyaz-core :9460 ──▶ luyaz-ui (touchscreen, DRM/KMS)
       ▲   └──▶ lpac ──▶ eUICC card
browser ──▶ luyaz-web :9090 ──▶ luyaz-core
luyaz-sentinel: screen owner + watchdog
```

The UI only talks to luyaz-core over this local HTTP interface; it never calls ubus itself. luyaz-core polls the system and serves JSON, and also carries the eSIM, APN and similar actions.

## Features

- Five bottom tabs, organised by what you want to do: **Home · Cellular · Wi-Fi · Exit · System**. The big line on Home is a one-sentence verdict, e.g. 「网络正常」 (network OK), 「信号偏弱」 (weak signal).
- Cellular: carriers, signal, network mode, APN, SIM and eSIM switching (through luyaz-core, which drives lpac).
- Exit: public exit IP and its location; Tailscale. No proxy features; if you want one, see [docs/PROXY.md](../docs/PROXY.md).
- System: brightness, screen timeout, light / dark / auto theme, language, battery and load, alert details.
- Phone plugged into the USB-C port: like the stock screen, it asks what it is for — charge + internet (the phone gets a USB network), 18 W fast charging, or an Ethernet adapter — and can remember the answer (System › When a phone is plugged in).
- Every tap gets immediate feedback; actions that need confirming take two taps.
- **luyaz-sentinel** is the single owner of the screen. It starts or takes over the UI, restarts it after a crash and records an alert. If the UI fails to come up twice in a row it hands the screen back to the stock UI (so the firmware does not escalate to a full reboot); long-press the bottom-right corner to come back.

## Quick start

To install on a device, follow the manager repo's **[getting-started guide](../docs/GETTING-STARTED.md)**. The install kit (`onboard/`) builds this UI and puts it on the device together with luyaz-core, luyaz-web and luyaz-sentinel. For updating a single component on a device that is already set up, see [docs/SHIP.md](docs/SHIP.md) (staged side-by-side test, atomic swap, rollback).

## Build

With Docker:

```sh
rs/setup-src.sh              # once: puts the patched LVGL + FreeType sources into a Docker volume
rs/build.sh device [FILE]    # → target/aarch64-unknown-linux-musl/release-device/luyaz-ui
rs/build.sh test             # cargo test
```

Builds run with cargo zigbuild in the shared build image (`onboard/build.Dockerfile`). LVGL is pinned to v9.5. The install kit's `onboard/build-kit.sh` calls `rs/build.sh device` itself.
The touch UI fonts (Nunito and a CJK fallback) are generated by `scripts/fonts/build-nunito.sh` and `scripts/fonts/build-cjk-fallback.sh` (public downloads pinned by sha256); the install kit runs them automatically.

Code layout: entry point `rs/devui/src/main.rs`, screens in `rs/devui/src/ui/`, widgets `kit.rs`, palette `theme.rs`, display/touch in `rs/plat`. Off-screen render tests are in `rs/devui/src/render/` (`rs/smoke.sh`, `rs/parity.sh`); `scripts/test/docker.sh` runs the on-device script tests in a busybox container. Design rules: [docs/DESIGN.md](../docs/DESIGN.md) §4 (Chinese). More in [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

The earlier C version was removed and is kept under the git tag `legacy-c-touch-ui`; the even older litehtml renderer is under the tag `legacy-litehtml`.

## On the device

> **Never overwrite the live binary on the device with a new build.** A build that crashes on start is escalated by the firmware into a reboot loop, and a screen with no UI for a few minutes also triggers a full reboot.
> Test under a different file name first; the steps are in [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) and [docs/SHIP.md](docs/SHIP.md).

Layout: the UI is `/data/luyaz/ui/luyaz-ui` (process name `luyaz-ui`); its settings `devui.conf`, the `operator-logos/` folder and the fonts are in `/data/luyaz/ui/` as well. luyaz-sentinel (`/etc/init.d/luyaz-sentinel`) starts the UI; the UI does not start itself.

## Reliability scripts

`scripts/` holds the on-device scripts used with the manager repo (contract in [docs/RELIABILITY.md](../docs/RELIABILITY.md)): procd init scripts (`luyaz-core.init`, `luyaz-web.init`, `luyaz-sentinel.init`), the ship executor and boot recovery (`u60-ship.sh`, `u60-recover.sh`), a read-only health check (`doctor.sh`), config backup (`config-backup.sh`) and more.
