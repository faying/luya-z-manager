# Luya-Z Touch UI

**English** · [中文](README.zh-CN.md)

Part of **Luya-Z**: an open-source replacement UI for the 3.5-inch front-panel touchscreen of a 5G portable hotspot: Rust + LVGL + FreeType drawing straight to DRM/KMS, built as one static aarch64 binary (`luyaz-ui`), plus the on-device scripts.
It lives in the `touch-ui/` directory of the [Luya-Z Manager](../README.md) repository and is built and installed together with it.

> **Hardware:** runs on the ZTE U60 Pro (MU5250). Community project, not affiliated with ZTE. Use at your own risk.

## How it fits

```
luyaz-core :9460 ──▶ luyaz-ui (touch screen)
       ▲  └──▶ lpac (/data/esim) ──▶ eUICC card
browser ──▶ luyaz-web :9090 (admin web) ──▶ luyaz-core
luyaz-sentinel: screen owner + watchdog
```

The touch UI reads live data from the core `luyaz-core` (`/v2/state` + `/v2/events` on `127.0.0.1:9460`; the home card and status bar verdicts come ready-made from `/v2/screen`), and sends eSIM, APN and other actions to the core's control API.
The screen owner is `luyaz-sentinel` (manager `crates/luyaz-sentinel`). The manager install kit puts all of them on the device together.

## Features

- Five bottom tabs, organised by what you want to do: **Home · Cellular · Wi-Fi · Exit · System**. The big line on Home is a one-sentence verdict, e.g. 「网络正常」 (network OK), 「信号偏弱」 (weak signal), 「漫游中」 (roaming).
- Cellular: carriers, signal, network mode, APN, SIM and eSIM switching (through the core, which drives lpac).
- Exit: public exit IP and its location; Tailscale. No proxy features; if you want one, see the manager's [docs/PROXY.md](../docs/PROXY.md).
- System: brightness, screen timeout, light / dark / auto theme, battery and load, alert details.
- Phone plugged into the USB-C port: like the stock screen, it asks what it is for — charge + internet (the phone gets a USB network), 18 W fast charging, or an Ethernet adapter — and can remember the answer (System › When a phone is plugged in).
- Every tap gets immediate feedback; actions that need confirming take two taps.
- Screen owner (`luyaz-sentinel`): starts or takes over the UI, restarts it after a crash and records an alert. If the UI fails to start twice in a row it hands the screen back to the stock UI (so the firmware does not escalate to a full reboot); long-press the bottom-right corner for 3 seconds to come back.
- `scripts/`: procd init scripts (`luyaz-core.init`, `luyaz-web.init`, `luyaz-sentinel.init`), a read-only health check (`doctor.sh`, a thin shim over `luyaz-core doctor`), alert helpers, config backup (`config-backup.sh`), the ship executor and boot-time recovery (see [docs/SHIP.md](docs/SHIP.md), Chinese) and more. The contract is in the manager's [docs/RELIABILITY.md](../docs/RELIABILITY.md).

## Quick start

To install on a device, follow the manager's **[getting-started guide](../docs/GETTING-STARTED.md)**. The touch UI goes onto the device with that install kit; on a device that is already set up, update with `./install.sh devui`.

## Build

With Docker (shared Rust build image; no local toolchain needed):

```sh
rs/setup-src.sh              # once: patched LVGL v9.5.0 + FreeType 2.13.3 sources into a docker volume
rs/build.sh device out/luyaz-ui   # static aarch64-musl luyaz-ui (cargo zigbuild)
```

The crates in `rs/` are members of the manager Cargo workspace. The manager's `onboard/build-kit.sh` builds the touch UI by itself when no prebuilt binary is given.
The touch UI fonts (Nunito and a CJK fallback) are generated by `scripts/fonts/build-nunito.sh` and `scripts/fonts/build-cjk-fallback.sh` (public downloads pinned by sha256); the install kit runs them automatically.

Tests: `scripts/test/docker.sh` (on-device scripts, fully stubbed in a busybox container), `rs/build.sh test` (Rust unit tests),
and `rs/smoke.sh` (off-screen end-to-end run against a fake core). Development details are in [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

> **Never overwrite the live binary on the device with a new build.** A build that crashes on start is escalated by the firmware into a reboot loop, and a screen with no UI for a few minutes also triggers a full reboot.
> Test under a different file name first; the steps are in [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md#trying-a-new-build-on-a-real-device).
